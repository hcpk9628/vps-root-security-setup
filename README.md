## 为什么 root 权限这么重要

root 是 Linux 系统的最高权限账户。有 root，你才能：

- 安装任意软件包和依赖（nginx、PostgreSQL、Redis、Docker，随便装）；
- 修改系统级配置，比如内核参数、systemd 服务、定时任务；
- 绑定 1024 以下端口、管理所有用户和文件权限；
- 使用 tun/tap 设备搭建 VPN——搬瓦工官方明确支持 PPP 和 VPN（tun/tap）。

注意一个边界：服务商明确禁止 open proxy（开放代理），这类配置极易被滥用扫描，是 ToS 明令限制的对象。自己用、加密认证的 VPN 没问题，但对公网完全开放的代理端口会被封。

很多共享主机和部分廉价 VPS 不给完整 root，或者用容器虚拟化限制你改内核、装不了 Docker。搬瓦工全线用 KVM 虚拟化，这是一台“完整的虚拟机”，内核随便换、ISO 可以手动挂载安装，root 权限也是所有套餐标配。这也是为什么它常被当作 unmanaged VPS 的入门候选——KVM + root 这套组合在同类服务里不算多见。

## 拿到 root 之后，先做这五件事

拿到服务器的第一小时，比后面一个月都关键。以下步骤适用于任何 unmanaged VPS，不限于搬瓦工：

1. **上传你的 SSH 公钥，禁用密码登录。** 默认密码登录会被全网扫描器轰炸。把公钥放进 `~/.ssh/authorized_keys`，然后在 `/etc/ssh/sshd_config` 里把 `PasswordAuthentication` 设为 `no`。这一步做完，99% 的暴力破解尝试直接失效。
2. **更新系统。** Debian/Ubuntu 跑 `apt update && apt upgrade`，RHEL 系用 `dnf upgrade`。新装系统往往带着一堆待修的安全补丁。
3. **建一个普通用户，日常不用 root 登录。** 误操作 `rm -rf` 这种事故，root 和普通用户的后果完全不同。需要提权时用 sudo。
4. **配置防火墙。** 用 `ufw` 或 `firewalld` 只放行 22（或你改过的 SSH 端口）、80、443，其余默认拒绝。KiwiVM 面板本身不替代系统防火墙，两层都要做。
5. **先拍一个快照。** KiwiVM 的 snapshot 功能是免费的，在折腾任何大改动之前拍一张，出问题一键回滚，比重新装系统快得多。

这五步做完，你的服务器就有了基本的安全底线。之后的 Web 服务、数据库、Docker 都是在这个底座上盖楼。
